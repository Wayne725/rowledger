# RowLedger Studio 使用指南

日期：2026-10-08 · 版本：0.2.0 預覽版

Studio 是在本機瀏覽器使用的訂單／收款核對工作台，會保存批次、原始檔與人工決策。適用單人、一筆訂單對一筆收款。

## 啟動

依 [README](../README.md) 安裝 Python 套件後，在終端執行：

```sh
rowledger studio --workspace runs/studio
```

開啟終端印出的 `http://127.0.0.1:8765`。使用「試用合成範例」可直接體驗 26 筆資料、5 組自動配對、16 筆待確認；這些不是客戶資料。預設埠被占用時加 `--port 8766`，並開啟新的印出網址。

完成後在終端按 Ctrl+C 停止服務。再次執行相同命令會載入已保存的進度；只有關閉網頁不會停止服務。不要更換 workspace 路徑，除非要建立獨立工作台。

## 匯入與欄位設定

按「＋」新增批次，填名稱，選擇訂單與收款的 CSV 或 XLSX。「欄位與工作表設定」可調整兩側編號、金額、幣別欄位與 Excel 工作表。預設欄名是 `order_id`、`amount`、`currency`；多工作表 Excel 必須指定工作表名稱。

幣別小數位例如 `USD=2, EUR=2, TWD=0, JPY=0`，應依實際來源系統設定。程式不自動換匯、猜測金額或四捨五入。Excel 編號應儲存為文字；已丟失的前導零不會被推測復原。

每份輸入最多 10 MiB、25,000 筆、100 欄。CSV 必須是 UTF-8、逗號分隔。格式錯誤、重複標題或超出限制的匯入會被拒絕，不產生部分批次。

相同檔案位元組、檔名及設定再次匯入時，會開啟既有批次，保留名稱與決策。檔案或設定改變就建立新批次，不自動複製舊審核。

## 確認與撤回

用搜尋及結果／來源篩選找資料，按「查看」檢查原始欄位與來源位置；每頁最多 50 筆。

在合成範例中，選取訂單 `00047`（record 8）與收款 `0047`（record 7），填確認人與原因，再按「確認配對並保存」。兩筆幣別及金額必須完全相同；無效資料、已配對資料不能被強制配對。保存後得到 6 組配對、14 筆待確認，重新整理仍保留。

切換到「人工配對」，查看其中一筆，填寫變更原因，可「撤回這筆人工配對」。撤回會移除整組配對，舊決策仍留在操作紀錄。姓名是自行填寫，沒有身分驗證。

已保存的決策立即寫入本機。還沒按保存的選取、姓名、原因文字不保證保留。多個視窗同時開啟時，過期版本的修改會被拒絕並重新載入，請依最新內容操作。

## 關閉與重新開啟

關閉前填確認人及原因；仍有差異時須勾選明確確認。**關閉只凍結當期工作，不代表款項已結清。** 待確認數及未解決來源資料不會被清零。

已關閉的批次可以查看、匯出，不能更改配對。填原因後「重新開啟批次」可繼續處理。兩種狀態變更都保留當時未解決資料的紀錄。

## 匯出、備份與資料保管

「匯出完整結果」產生 ZIP，包含：

- `report.html`：可離線開啟的互動報告。
- `results.json`、`results.xlsx`：結果、原始欄位及人工配對；Excel 文字不會變成可執行公式。
- `review-template.json`：綁定本次來源的決策文件。
- `workspace.json`：批次狀態、版本與完整操作紀錄。
- `inputs/orders/`、`inputs/payments/`：位元組完全相同的原始檔。
- `manifest.json`：其餘所有匯出檔的 SHA-256 檢查碼。

請確認瀏覽器下載已完成。ZIP 是可攜紀錄，尚不能直接匯回工作台。在匯出的 `report.html` 新增決策不會回寫 Studio；它遵循 [CLI 使用指南](使用指南.md) 的匯出審核流程。

要備份可恢復的工作台，先 Ctrl+C 停止 Studio，再複製整個 workspace 資料夾。恢復時將備份複製到另一個資料夾，用 `--workspace` 指向它。不要在服務運作中直接複製資料庫檔。

資料庫 `studio.sqlite3`、ZIP 與報告都包含原始資料且未加密，應保存在私有位置。不要提交真實資料到 GitHub。預設 `runs/` 被 Git 忽略，自訂路徑需自行確認。

## 使用邊界

這是本機單人預覽版，不提供團隊權限、登入、不可竄改稽核、銀行／ERP 串接、退款、手續費或拆合單。配對核心與原版一致，仍是一對一精確核對。

服務只綁定 `127.0.0.1`，使用本機 session、Host／Origin 檢查與 CSP 限制跨來源存取；它不能防止其他有本機存取權的程式或使用者讀取資料。不要用反向代理或埠轉送對外公開。檔案限制不是全面惡意檔案沙箱。
